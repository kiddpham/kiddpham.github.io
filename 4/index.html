Part 2: Fit a Neural Radiance Field from Multi-View Images
Part 2.1: Create Rays from Cameras

I implemented three key functions to convert pixel coordinates into 3D rays for NeRF rendering:

1. transform(c2w, x_c): Transforms points from camera space to world space using the camera-to-world (c2w) extrinsic matrix. The function handles both single points and batched coordinates by converting to homogeneous coordinates, applying the transformation matrix, and converting back to 3D.

2. pixel_to_camera(K, uv, s): Converts 2D pixel coordinates (u,v) to 3D camera coordinates using the camera intrinsic matrix K. Given focal lengths (fx, fy) and principal point (cx, cy), it computes the 3D point at depth s using the inverse projection equations: x_c = (u - cx) * s / fx, y_c = (v - cy) * s / fy, z_c = s.

3. pixel_to_ray(K, c2w, uv): Generates rays for ray marching by combining the previous functions. The ray origin is extracted directly from the c2w translation vector (camera position in world space). The ray direction is computed by transforming a point at depth=1 in camera space to world space, then normalizing the vector from the camera origin to that point.
Part 2.2: Sampling

I implemented two sampling functions:

1. sample_rays_from_images: Randomly samples N rays from the training images. For each ray, it randomly selects an image, picks a random pixel coordinate (with +0.5 offset for pixel center), retrieves the ground truth RGB color, and generates the ray using pixel_to_ray(). This ensures diverse scene coverage during training.

2. sample_along_rays: Discretizes each ray into sample points between near and far bounds. It creates uniformly spaced points along the ray using np.linspace(), then adds random perturbation during training to prevent overfitting to fixed positions. The 3D coordinates are computed as x = ray_origin + ray_direction * t. I used near=2.0, far=6.0, and n_samples=64 for the lego scene.
Part 2.3: Putting the Dataloader All Together

I implemented the RaysDataset class to manage ray sampling from multi-view images. The dataset precomputes all rays during initialization by creating a pixel grid for each image, extracting RGB colors, and generating rays using pixel_to_ray(). All ray origins, directions, and target colors are stored in arrays with shape (N*H*W).

The sample_rays() method randomly samples rays by generating random indices and returning a dictionary with 'rays_o', 'rays_d', and 'pixels'. I verified correctness with the UV indexing test to ensure pixels map correctly to the original images. Precomputing rays improves training efficiency by eliminating redundant computation.
Part 2.4: Neural Radiance Field

I implemented the NeRF network to predict density and view-dependent color for 3D points. The network takes two inputs: 3D position (x,y,z) and 3D view direction, both with positional encoding (L=10 for position, L=4 for direction). The architecture has 8 fully-connected layers with 256 hidden units and a skip connection at layer 5 that concatenates the input position encoding.

The first 8 layers process the position to output density (with ReLU activation to ensure positive values). Then the network adds the view direction encoding and processes it through 2 additional layers to output RGB color (with Sigmoid to constrain values to [0,1]). This allows the network to model view-dependent effects like specular reflections, where the same 3D point appears different from different viewing angles.
Part 2.5: Volume Rendering

I implemented the volume rendering equation to convert density and color predictions into final pixel colors. The volrend() function takes predicted densities (sigmas), colors (rgbs), and step_size as inputs. It computes alpha values (opacity) for each sample using alpha = 1 - exp(-sigma * step_size), representing the probability that a ray terminates at each point.

The transmittance T is computed using cumulative product of (1 - alpha), representing the probability that the ray reaches each sample without terminating earlier. I concatenate ones at the start and shift by one position to get the correct transmittance values. The final rendered color is the weighted sum of all colors along the ray, where weights = T * alpha. I verified correctness using the provided test case.

Part 2.6: Training with Your Own Data
Part 2.6 differs from the earlier Part 2 sections because it no longer uses the perfectly preprocessed Lego dataset. Instead, it relies on my own captured images, which require additional preprocessing steps that the Lego pipeline never needed: undistortion, ROI cropping, resizing to a consistent resolution, and focal-length rescaling. It also adds pose-quality filtering to remove bad c2w matrices, something unnecessary with Lego's ground-truth poses. Another key change is how the depth bounds are handled—Lego uses a fixed [2.0, 6.0] range, while Part 2.6 computes near/far automatically based on actual camera distances, since the real scene scale isn’t known. Finally, rendering uses my own test poses instead of Lego’s synthetic orbit. Everything else (NeRF architecture, ray sampling, training loop) remains unchanged.
